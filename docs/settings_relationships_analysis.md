# 설정 항목 관계 분석 및 UI 개선안

작성일: 2025-10-09  
목적: 설정 UI의 항목 간 관계를 분석하고 사용자 친화적인 재배치 방안 제시

---

## 1. 현재 문제점

### 1.1 관련 설정의 분산 배치
- **동시성 관련**: `최대 동시 요청`, `목록 동시 처리`, `상세 동시 처리`가 UI에서 떨어져 있음
- **타임아웃 관련**: `요청 타임아웃(초)`, `페이지 타임아웃`, `상세 타임아웃`이 분산됨
- **Rate Limit**: `초당 요청 제한(RPS)`이 동시성 설정과 분리됨

### 1.2 설명 부족
- 마우스 호버 시 추가 설명 없음
- 각 설정의 용도와 위험성 표시 없음
- 설정 간 상호작용 안내 없음

### 1.3 시각적 그룹핑 부재
- 유사 기능끼리 묶이지 않음
- Separator나 카테고리 구분 없음
- 위험한 설정에 대한 시각적 경고 없음

## 2. 설정 항목 상세 분석

### 2.1 동시성 제어 설정 (Concurrency Control)

#### A. `최대 동시 요청` (user.max_concurrent_requests)
```typescript
// UI: "동시에 보낼 수 있는 요청 개수"
// 기본값: 3, 범위: 1-100
```

**실제 사용처**:
- `actor_system.rs`: 전체 시스템의 동시성 제한
- `smart_crawling.rs`: 스마트 크롤링의 concurrency_limit
- `shallow_sync_commands.rs`: Shallow sync 작업의 동시성

**역할**: 
- **전역 동시성 상한선** (Global concurrency cap)
- 모든 크롤링 작업이 이 값을 초과하지 않음
- 서버 부하 보호를 위한 최종 제한

**영향**:
- ⚠️ **목록/상세 동시 처리보다 작으면 해당 값들이 무의미해짐**
- ⚠️ 너무 높으면 서버가 429 (Too Many Requests) 응답 가능
- ⚠️ 너무 낮으면 크롤링 속도 저하

#### B. `목록 동시 처리` (crawler.initial_concurrency)
```typescript
// UI: "리스트 페이지 처리 동시성"
// 기본값: 16, 범위: 1-100
```

**실제 사용처**:
- `ComprehensiveCrawlerConfig.initial_concurrency`
- 목록 페이지(리스트) 크롤링 시 사용

**역할**:
- 제품 목록 페이지를 가져올 때 동시에 처리할 페이지 수
- 예: initial_concurrency=16이면 16개 페이지 동시 요청

**제약**:
- ✅ `max_concurrent_requests`보다 작거나 같아야 효과적
- 예: max=3, initial=16 → 실제로는 3개만 동시 처리

#### C. `상세 동시 처리` (crawler.detail_concurrency)
```typescript
// UI: "상세 페이지 처리 동시성"
// 기본값: 16, 범위: 1-100
```

**실제 사용처**:
- `ComprehensiveCrawlerConfig.detail_concurrency`
- 제품 상세 페이지 크롤링 시 사용

**역할**:
- 제품 상세 페이지를 가져올 때 동시에 처리할 페이지 수
- 예: detail_concurrency=16이면 16개 상세 페이지 동시 요청

**제약**:
- ✅ `max_concurrent_requests`보다 작거나 같아야 효과적
- ⚠️ 상세 페이지는 목록보다 무거우므로 너무 높으면 타임아웃 위험

### 2.2 Rate Limiting (속도 제한)

#### `초당 요청 제한 (RPS)` (worker.max_requests_per_second)
```typescript
// UI: "초당 최대 요청 수"
// 기본값: 10, 범위: 1-100
```

**실제 사용처**:
- `simple_http_client.rs`: GlobalRateLimiter
- Token bucket 알고리즘으로 초당 요청 수 제한

**역할**:
- **글로벌 Rate Limiter** (전역 속도 제한기)
- 1초에 최대 N개 요청만 허용
- 서버의 429 응답 방지

**동시성과의 관계**:
```
예시 1: max_concurrent=10, RPS=5
→ 10개 작업이 대기 중이지만, 1초에 5개씩만 실행
→ 2초에 걸쳐 10개 완료

예시 2: max_concurrent=3, RPS=20
→ 최대 3개만 동시 실행, RPS 제한은 느슨함
→ 3개가 빠르게 완료되고 다음 3개 시작

결론: RPS는 "시간당 처리량", max_concurrent는 "동시 작업 수"
→ 둘 다 제한으로 작용하며, 더 엄격한 쪽이 실제 제한
```

**권장 관계**:
- ✅ `RPS >= max_concurrent_requests` (일반적)
- ⚠️ `RPS < max_concurrent_requests` → RPS가 병목
- 예: max=10, RPS=5 → 실제로는 초당 5개만 처리

### 2.3 타임아웃 설정

#### A. `요청 타임아웃(초)` (user.crawling.advanced.request_timeout_seconds)
```typescript
// UI: "HTTP 요청 타임아웃"
// 기본값: 90, 범위: 5-300
```

**역할**: 
- 단일 HTTP 요청의 최대 대기 시간
- 서버 응답이 늦을 때 중단

#### B. `페이지 타임아웃` (crawler.page_timeout_ms)
```typescript
// ComprehensiveCrawlerConfig
// 기본값: 90000 (90초)
```

**역할**:
- 목록 페이지 로딩 최대 시간
- 브라우저 렌더링 대기 시간 포함

#### C. `상세 타임아웃` (crawler.product_detail_timeout_ms)
```typescript
// ComprehensiveCrawlerConfig
// 기본값: 90000 (90초)
```

**역할**:
- 상세 페이지 로딩 최대 시간
- 무거운 페이지 대응

**관계**:
- ⚠️ `상세 동시 처리`가 높고 `상세 타임아웃`이 짧으면 많은 실패 발생
- ✅ 동시성 ↑ → 타임아웃 ↑ 권장

## 3. 설정 간 상호작용 매트릭스

| 설정 A | 설정 B | 관계 | 권장사항 |
|--------|--------|------|----------|
| `max_concurrent_requests` | `목록 동시 처리` | A는 B의 상한 | B ≤ A |
| `max_concurrent_requests` | `상세 동시 처리` | A는 B의 상한 | B ≤ A |
| `max_concurrent_requests` | `초당 요청 제한 (RPS)` | 독립적이나 조합 효과 | RPS ≥ A (일반적) |
| `목록 동시 처리` | `페이지 타임아웃` | 동시성 ↑ → 타임아웃 필요 | 고동시성 시 타임아웃 ↑ |
| `상세 동시 처리` | `상세 타임아웃` | 동시성 ↑ → 타임아웃 필요 | 고동시성 시 타임아웃 ↑ |
| `초당 요청 제한` | `요청 타임아웃` | RPS 낮음 → 대기 증가 | 균형 필요 |

### 4.4 자동 검증 및 경고

```typescript
// 설정 조합 검증
function validateConcurrencySettings(settings) {
  const warnings = [];
  
  // 경고 1: 목록/상세 동시성이 최대 동시 요청보다 큼
  if (settings.list_concurrency > settings.max_concurrent_requests) {
    warnings.push({
      type: 'warning',
      message: '⚠️ 목록 동시 처리가 최대 동시 요청보다 큽니다. 실제로는 ${settings.max_concurrent_requests}개만 동시 실행됩니다.'
    });
  }
  
  // 경고 2: RPS가 너무 낮음
  if (settings.rps_limit < settings.max_concurrent_requests) {
    warnings.push({
      type: 'info',
      message: '💡 초당 요청 제한이 최대 동시 요청보다 낮습니다. 초당 ${settings.rps_limit}개만 처리됩니다.'
    });
  }
  
  // 경고 3: 고동시성 + 저타임아웃
  if (settings.detail_concurrency > 10 && settings.detail_timeout_ms < 60000) {
    warnings.push({
      type: 'warning',
      message: '⚠️ 높은 동시성과 짧은 타임아웃 조합은 많은 실패를 유발할 수 있습니다.'
    });
  }
  
  return warnings;
}
```

## 7. 결론

### 현재 문제
1. **관련 설정 분산**: 동시성/타임아웃 설정이 흩어져 있음
2. **설명 부족**: 각 설정의 용도와 위험성 불명확
3. **관계 미표시**: 설정 간 상호작용 안내 없음

### 개선 방향
1. **논리적 그룹핑**: 동시성/타임아웃/재시도 등으로 분류
2. **상세 툴팁**: 마우스 호버 시 용도/영향/권장값 표시
3. **자동 검증**: 부적절한 조합 시 경고

### 기대 효과
- ✅ 사용자가 설정 간 관계를 쉽게 이해
- ✅ 실수로 인한 크롤링 실패 감소
- ✅ 최적 성능 설정 유도
