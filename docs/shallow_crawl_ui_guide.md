## 📊 **버튼별 기능**

### **1. 🏃 빠른 동기화** (Shallow Sync)

**용도**: 전체 페이지의 URL과 좌표만 빠르게 갱신

**동작**:
- 전체 568페이지 리스팅 크롤링
- `products` 테이블에 URL + page_id + index_in_page 저장
- `product_details` 크롤링은 **스킵**

**소요 시간**: 5-8분

**사용 시나리오**:
```
1. 사이트 순서가 변경된 것 같을 때
2. 진단 전에 좌표를 먼저 정리하고 싶을 때
3. 빠른 데이터 스냅샷이 필요할 때
```

**로그 예시**:
```
[14:30:22] 🏃 빠른 동기화 시작 (좌표 갱신만)
[14:35:18] ✅ 빠른 동기화 완료: 568페이지, 6,816개 URL 동기화 (296,450ms)
[14:35:18] 💡 이제 '📊 누락 분석' 또는 '🧠 스마트 동기화'를 실행하세요.
```

---

### **2. 📊 누락 분석** (Analyze Missing)

**용도**: 누락된 `product_details` 확인

**동작**:
- SQL 쿼리로 누락 제품 추출
- 결과를 로그에 표시

**소요 시간**: 1초 미만

**사용 시나리오**:
```
1. 빠른 동기화 후 누락 확인
2. 보완 크롤링 전에 누락 규모 파악
3. 데이터 완전성 체크
```

**로그 예시**:
```
[14:36:01] 📊 누락 제품 분석 중...
[14:36:02] 📊 분석 완료: 전체=6816, 완료=6147, 누락=669
[14:36:02] ⚠️ 669개 제품의 상세 정보가 누락되었습니다.
[14:36:02] 💡 '🧠 스마트 동기화'로 자동 보완 가능합니다.
[14:36:02]   - Samsung SmartThings Hub (https://...)
[14:36:02]   - Philips Hue Bridge (https://...)
[14:36:02]   - Aqara Hub M2 (https://...)
[14:36:02]   ... 외 666개
```

---

### **3. 🧠 스마트 동기화** (Smart Sync)

**용도**: 얕은 크롤링 + 진단 + 누락 보완 자동 실행

**동작**:
1. **Phase 1**: 빠른 동기화 (좌표 갱신)
2. **Phase 2**: 누락 분석
3. **Phase 3**: 누락된 URL만 선택적 크롤링

**소요 시간**: 8-12분 (누락 규모에 따라)

**사용 시나리오**:
```
1. 한 번에 전체 데이터 정리
2. 주기적인 전체 동기화 (주 1회 권장)
3. 중요한 작업 전 데이터 완전성 보장
```

**로그 예시**:
```
[14:40:00] 🧠 스마트 동기화 시작 (얕은 크롤링 + 진단 + 보완)
[14:45:30] 📝 Phase 1 완료: 568페이지 동기화 (330,500ms)
[14:45:31] 📊 Phase 2 완료: 669개 누락 발견
[14:50:12] 🔧 Phase 3 완료: 665/669개 보완 (281,200ms)
[14:50:12] ⚠️ 4개 실패
[14:50:12] 🎉 스마트 동기화 완료! (총 612.1초)
```

## 💡 **성능 팁**

### **시간 절약**
1. **빠른 동기화 먼저**: 좌표 정리 후 누락 파악

## 🔧 **트러블슈팅**

### **Q: 빠른 동기화 후에도 누락이 많다?**
**A**: 정상입니다. 빠른 동기화는 좌표만 갱신하므로, 누락 분석 후 스마트 동기화를 실행하세요.

### **Q: 스마트 동기화가 실패한다?**
**A**: 로그에서 실패한 URL을 확인하고, 수동 크롤링으로 재시도하거나 사이트 접근성을 확인하세요.

### **Q: 누락 분석 결과가 이상하다?**
**A**: 먼저 빠른 동기화로 좌표를 정리한 후 다시 누락 분석을 실행하세요.
