## 1️⃣ 📝 로깅 설정 (6개)

### 위험도 분포
- 🟢 안전: 3개 (50%)
- 🟡 주의: 3개 (50%)
- 🔴 위험: 0개 (0%)

### 상세 분석

#### 🟢 안전한 설정 (3개)
1. **auto_cleanup_logs** - 종료 시 로그 정리
   - 기본값: false
   - 권장: true
   - 영향: 디스크 공간 관리에만 영향

2. **keep_only_latest** - 최신 로그만 유지
   - 기본값: false
   - 권장: false (여러 세션 로그 보관 시)
   - 영향: 과거 로그 추적 가능 여부

3. **concise_startup** - 간결한 시작 로그
   - 기본값: true
   - 권장: true
   - 영향: 시작 로그 상세도만 변경

#### 🟡 주의가 필요한 설정 (3개)
1. **file_naming_strategy** - 파일 이름 전략
   - 기본값: "unified"
   - 권장: "unified" 또는 "daily"
   - ⚠️ 주의: timestamp는 파일이 많아질 수 있음

2. **max_files** - 로그 보관 최대 개수
   - 기본값: 5
   - 권장: 5-10개
   - ⚠️ 주의: 너무 작으면 과거 로그 손실, 너무 크면 디스크 공간 부족

3. **separate_frontend_backend** - 로그 파일 분리
   - 기본값: false
   - 권장: true (문제 추적 시 유용)
   - ⚠️ 주의: true 설정 시 로그 파일 2배

## 2️⃣ 🔄 재시도 정책 (4개)

### 위험도 분포
- 🟢 안전: 0개 (0%)
- 🟡 주의: 0개 (0%)
- 🔴 **위험: 4개 (100%)** ⚠️⚠️⚠️

### ⚠️ 전체 위험 구역 - 신중한 조정 필요!

#### 🔴 위험한 설정 (4개)
1. **batch_retry_limit** - 배치 재시도 횟수
   - 기본값: 3
   - 권장: 3-5회
   - ⚠️ 위험:
     - 너무 높으면 시스템 과부하
     - 5회 초과는 비효율적
     - 무한 재시도 방지 필요

2. **product_list_retry_count** - 목록 재시도
   - 기본값: 9
   - 권장: 3-5회 (기본값 높음!)
   - ⚠️ 위험:
     - 높은 값은 느린 응답 시간
     - 목록 페이지는 중요하므로 적절한 재시도 필요

3. **product_detail_retry_count** - 상세 재시도
   - 기본값: 9
   - 권장: 3-5회 (기본값 높음!)
   - ⚠️ 위험:
     - 높은 값은 전체 크롤링 시간 증가
     - 상세 페이지는 개별 실패 허용 가능

4. **max_retries** - HTTP 요청 재시도
   - 기본값: 5
   - 권장: 3-5회
   - ⚠️ 위험:
     - 과도한 재시도는 자원 낭비
     - 네트워크 일시 오류 대응 필요

**🎯 재시도 정책 권장사항**:
- 모든 재시도 설정을 3-5회로 통일 권장
- 기본값(9회)는 과도하게 높음
- `retry_delay_ms`와 함께 조정 필요

## 3️⃣ 🌐 네트워크 및 워커 (5개)

### 위험도 분포
- 🟢 안전: 2개 (40%)
- 🟡 주의: 2개 (40%)
- 🔴 위험: 1개 (20%)

### 상세 분석

#### 🟢 안전한 설정 (2개)
1. **user_agent** - HTTP User-Agent
   - 영향: 봇 감지에만 영향
   - 권장: 실제 브라우저와 유사한 값

2. **user_agent_sync** - 동기화 전용 User-Agent
   - 영향: 추적 용이성
   - 권장: 기본값과 다른 값 사용

#### 🟡 주의가 필요한 설정 (2개)
1. **follow_redirects** - 리다이렉트 추적
   - 기본값: true
   - ⚠️ 주의: 무한 리다이렉트 가능성

2. **respect_robots_txt** - robots.txt 준수
   - 기본값: false
   - 권장: false (내부 테스트), true (공개 크롤링)
   - ⚠️ 주의: true 설정 시 일부 페이지 크롤링 불가

#### 🔴 위험한 설정 (1개)
1. **db_batch_size** - DB 배치 크기
   - 기본값: 100
   - 권장: 100-500개
   - ⚠️ 위험:
     - 너무 크면 메모리 부족 (1000+ 위험)
     - 너무 작으면 DB 쓰기 오버헤드
     - `db_max_concurrency`와 함께 조정

## 4️⃣ 💾 데이터베이스 (1개)

### 위험도 분포
- 🟢 안전: 0개 (0%)
- 🟡 주의: 0개 (0%)
- 🔴 **위험: 1개 (100%)** ⚠️⚠️⚠️

### 🔴 매우 중요한 설정!

**db_max_concurrency** - DB 동시 실행 수
- 기본값: 5
- 권장: 3-10개
- ⚠️ 위험:
  - 너무 높으면 DB 락 경합 (20+ 매우 위험)
  - 너무 낮으면 처리 속도 저하
  - SQLite는 동시성 제한이 있음
  - `db_batch_size`와 함께 조정 필수

**💡 DB 설정 조합 가이드**:
```
저사양: db_batch_size=100, db_max_concurrency=3
권장:   db_batch_size=200, db_max_concurrency=5
고사양: db_batch_size=500, db_max_concurrency=8
위험:   db_batch_size=1000+, db_max_concurrency=20+ (절대 금지)
```

## 5️⃣ ⏱️ 타이밍 및 스케줄링 (5개)

### 위험도 분포
- 🟢 안전: 1개 (20%)
- 🟡 주의: 2개 (40%)
- 🔴 위험: 2개 (40%)

### 상세 분석

#### 🟢 안전한 설정 (1개)
1. **stats_interval_seconds** - 통계 출력 간격
   - 기본값: 10초
   - 권장: 5-30초
   - 영향: 로그 출력 빈도만 변경

#### 🟡 주의가 필요한 설정 (2개)
1. **scheduler_interval_ms** - 스케줄러 간격
   - 기본값: 100ms
   - 권장: 100-1000ms
   - ⚠️ 주의: 너무 짧으면 CPU 과부하

2. **shutdown_timeout_seconds** - 종료 타임아웃
   - 기본값: 30초
   - 권장: 10-30초
   - ⚠️ 주의: 너무 짧으면 데이터 손실 가능

#### 🔴 위험한 설정 (2개)
1. **retry_delay_ms** - 재시도 대기 시간
   - 기본값: 2000ms
   - 권장: 1000-3000ms
   - ⚠️ 위험:
     - 너무 짧으면 서버 부하
     - 너무 길면 전체 시간 증가
     - 재시도 정책과 함께 조정

2. **operation_timeout_seconds** - 작업 타임아웃
   - 기본값: 300초 (5분)
   - 권장: 60-300초
   - ⚠️ 위험:
     - 너무 짧으면 작업 중단
     - 큰 크롤링은 충분한 시간 필요

## 6️⃣ ⚙️ 엔진 내부 (8개)

### 위험도 분포
- 🟢 안전: 0개 (0%)
- 🟡 주의: 3개 (37.5%)
- 🔴 **위험: 5개 (62.5%)** ⚠️⚠️⚠️

### ⚠️ 고급 사용자 전용 - 이해 없이 변경 금지!

#### 🟡 주의가 필요한 설정 (3개)
1. **max_search_attempts** - 탐색 시도 횟수
   - 기본값: 10
   - 권장: 5-10회
   - ⚠️ 주의: 너무 많으면 시간 낭비

2. **removal_grace_secs** - 세션 정리 유예
   - 기본값: 10초
   - 권장: 10-30초
   - ⚠️ 주의: 너무 짧으면 복구 기회 없음

3. **override_config_limit** - 설정 제한 무시
   - 기본값: true
   - 권장: true (지능형 계산 신뢰 시)
   - ⚠️ 주의: 예상보다 많은 페이지 크롤링 가능

#### 🔴 위험한 설정 (5개)
1. **last_page_search_start** - 탐색 시작 위치
   - 기본값: 100
   - 권장: 100-500 (사이트마다 다름)
   - ⚠️ 위험:
     - 잘못된 값은 불필요한 요청 증가
     - 사이트별 최적화 필요

2. **request_timeout_seconds** - 고급 요청 타임아웃
   - 기본값: 60초
   - 권장: 30-60초
   - ⚠️ 위험:
     - 너무 짧으면 느린 응답 실패
     - `operation_timeout_seconds`와 중복 가능

3. **product_selectors** - CSS 선택자
   - 기본값: ['.product-item', '.product-card']
   - 권장: 사이트 구조에 맞는 정확한 선택자
   - ⚠️ 위험:
     - **잘못된 선택자는 크롤링 완전 실패**
     - 복수 선택자는 쉼표로 구분
     - 변경 전 반드시 테스트 필요

4. **failure_threshold** - 실패 임계값
   - 기본값: 5
   - 권장: 5-10회
   - ⚠️ 위험:
     - 너무 낮으면 세션 조기 종료
     - 너무 높으면 무의미한 재시도 지속

5. **max_range_limit** - 지능형 모드 최대 범위
   - 기본값: 1000
   - 권장: 500-1000
   - ⚠️ 위험:
     - 너무 크면 과도한 크롤링
     - `page_range_limit`와 함께 고려
